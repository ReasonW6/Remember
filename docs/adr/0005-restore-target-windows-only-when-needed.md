# Restore target windows only when needed

Remember does not open, restore, or activate every recorded target during playback preflight. Passive pointer trajectory may follow an already visible compatible target, but it never waits for, restores, activates, or foreground-checks a window; unavailable motion is skipped while playback time continues. When an effective pointer operation or a targeted keyboard sequence is about to start on an existing minimized or hidden target, Remember restores and activates that window just in time, then applies the normal identity and geometry checks. Mouse gestures and keyboard sequences establish their foreground target only at the start so releases and focus-changing actions can complete naturally. An activation click is injected without waiting for the clicked window itself to become foreground, because launcher surfaces may close and open a different foreground window only after button release; the next effective targeted operation establishes its own foreground target when required. Owned transient menus and dropdown lists use their stable owner as the recording target; legacy recordings that contain a transient target may bind it only while that surface is already visible and are never allowed to restore or activate it independently.
