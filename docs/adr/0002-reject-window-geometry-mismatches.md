# Reject window geometry mismatches

Window-relative playback refuses the initial binding when a target's client-area size or DPI differs from the recording; there is no force-continue option. A recorded window move or resize gesture is replayed from the client-area origin captured at the gesture's button press, then its resulting client size becomes the bound target's current geometry. Other recorded actions such as maximize buttons or keyboard shortcuts may also change that current size without stopping recording or playback. DPI changes remain incompatible throughout because coordinate scaling would be required. A window may be partly off-screen, but every recorded target point must remain inside the current virtual desktop; Remember neither moves the window independently nor clamps an unreachable point. This behavior reproduces explicit window adjustment while avoiding pointer drift and unsafe DPI scaling.
